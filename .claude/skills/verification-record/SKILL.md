# 검증 기록 정리

확인한 결과를 "무엇을 / 어떻게 / 결과는"이 한눈에 보이는 문서로 남긴다.
문서 뼈대는 같은 폴더의 [template.md](template.md)를 따른다.

## 절차

1. **대상 파악:** 프로젝트 루트에 `VERIFICATION.md`가 있으면 읽고, 기존 장 번호·문체·요약 표에 맞춰 이어 쓴다. 없으면 `template.md`로 새로 만든다.
2. **결과 모으기:** 확인 항목마다 실제 근거를 확보한다.
   - 확인 스크립트·명령이 있으면 **직접 다시 실행**해 출력 원문을 받는다. 실데이터를 바꾸는 명령은 복사본이나 임시 폴더에서 실행한다.
   - 출력 원문 전체는 `docs/results/<이름>.txt`에 저장한다.
   - 사용자가 준 화면 캡처는 `docs/screenshots/<번호>-<설명>.png`(예: `3-cli-summary.png`)로 옮긴다. 번호는 기존 파일 다음부터.
3. **장 쓰기:** 확인 항목마다 장 하나를 아래 순서로 쓴다.
   - **대상:** 확인한 폴더·파일·URL (링크)
   - **방법:** 번호 목록. 다른 사람이 그대로 따라 할 수 있게 쓴다.
   - **결과:** `✅ n/n 통과` 한 줄 + 출력 원문 코드 블록(핵심 부분만, 전체는 txt 링크) + 표의 열이나 숫자의 의미 설명
   - 캡처가 있으면 "어디 화면인지 + 무엇을 봐야 하는지"를 한두 줄 적고 이미지를 연결한다. 전후 비교는 두 칸 표로 나란히 놓는다.
   - 진행 중 만난 문제는 `문제 | 원인 | 해결` 표로 남긴다.
4. **요약 표 갱신:** 문서 위쪽 `확인 항목 | 방법 | 결과` 표에 새 항목을 한 줄씩 추가하고, 확인 날짜를 오늘로 바꾼다.
5. **다시 확인하는 방법:** 맨 아래에 재실행 명령을 코드 블록으로 적고, 데이터를 건드리는지 여부를 한 줄 덧붙인다.
6. **보고:** 추가·변경한 장과 파일 목록을 알려 주고, 연결한 이미지·링크가 실제로 존재하는지 확인한 결과를 함께 말한다.

## 지킬 것

- **지어내지 않는다.** 실행하지 않은 결과, 보지 않은 캡처 내용은 쓰지 않는다. 실패(FAIL)도 그대로 적고 원인을 함께 쓴다.
- **민감 정보는 가린다.** 키·토큰·비밀번호·`.env` 값·실제 이메일은 출력 원문에서도 `***`로 바꾼다.
- 문체는 존댓말 "~입니다". 표와 짧은 문장 위주로 쓴다.
- 문서만 고친다. 앱 코드나 데이터는 수정하지 않는다.
